Features

From raw records to a decision you can defend

Machine learning on structured claims data, fully local: no paid APIs, and the data never leaves the machine. All data is synthetic.

🎯

Review under a workload cap

A calibrated gradient-boosting model, with the threshold chosen by cost (a missed claim counts 10× an unnecessary review) and at most 15% of claims sent to review.

🔍

Unusual-claim detection

An Isolation Forest flags the most unusual 2% of claims without needing fraud labels: a second opinion next to the score.

📊

Every score explained

SHAP shows which factors pushed each claim's score up or down, computed from the exact inputs that were scored.

📉

Drift check on every import

New data is compared with the training data. A drifted batch is flagged before the review workload doubles.

🤖

Checked investigation reports

Agents gather evidence through fixed, read-only tools; an LLM drafts findings; code checks every number, date and ID against the evidence.

👥

Four-eyes decisions

A different person escalates or clears the case, with a required reason. Enforced in the API and the database, and audited.

How it works

From a CSV to a reviewed case

Import

Rows are validated one by one; bad rows are reported, good ones kept, and the batch is checked for drift.

Score

The active model versions (checksum-verified) score each claim and flag unusual ones. Every score is stored with its inputs.

Investigate

Six read-only lookups collect evidence; qwen3:8b drafts findings; code checks the numbers and builds the summary.

Decide

A reviewer who didn't open the case escalates or clears it, with a reason that goes into the audit log.
